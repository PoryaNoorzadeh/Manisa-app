# M5.1 — Explicit manual scenes and control UX recovery

Version: 0.20.0+25. Scope: user-triggered local On/Off scenes; no schedules, rules, cloud execution, scene RGB/level actions, or background replay.

## Removal recovery

Native removal attempts have a 30-second bound, per-Activity ownership and identity tokens. Timeout releases retry; old callbacks cannot complete or clear a newer attempt. Activity destruction clears local guards. Current-fabric removal remains the default; failure does not silently forget a device. A separate explicit confirmation permits local-only list removal and explains that remote fabric removal is unconfirmed and factory reset may be needed. Local forgetting clears subscriptions/read tracking without claiming remote removal.

Serialize complete device-list read/modify/write mutations to prevent a concurrent metadata save from resurrecting a removed node; a failed write must not poison the queue. Persist device-list removal before best-effort room/favorite cleanup. A successful remote removal is remembered during the session, so a local persistence retry does not repeat unpair. Failures of the primary device store retain the device and show an error. Hardware confirmation of the reported deletion failure remains required.

## RGB UX

Remove the independent saturation control. A visible full-hue spectrum supports tap/drag and accessibility via Slider. Spectrum and interaction remain left-to-right in Persian. Preview during drag; exactly one explicit command on release, with saturation 1. White remains a separate explicit choice. Initial/confirmed color still comes from the device, including its actual saturation; no startup write, fabricated initial color or optimistic confirmation. Brightness remains separate.

## Manual scenes

- Named, editable, locally persisted definitions; 1–32 unique stable node/endpoint actions, each explicit On or Off (never Toggle).
- Sequential execution, one run at a time, command followed by an actual OnOff read. Result confirmed only if the read matches the requested value. One failed output does not stop others.
- Timeout is unknown: the command may have executed. No automatic retry. Explicit retry repeats only unconfirmed actions; setting the same state is idempotent.
- Missing/removed output remains visibly unavailable and is never silently reassigned by list order. Users can remove it in the editor. No device/endpoint substitution.
- Persist definitions only, never execution queues or results. App reopening loads scenes without executing. Leaving during a run is guarded; an explicit stop button or destruction cancels unsent actions after the in-flight request completes. Already-sent commands cannot be recalled.
- Save failures preserve the editor draft. Load errors block edits until resolved; no silent catalog overwrite.

## M5.2 — scene lighting (0.21.0+26)

Optional LevelControl and color targets accompany explicit On actions. Off actions contain no lighting targets. The editor exposes controls only for discovered capabilities; disabled options preserve the existing device setting. Scene colors are desired targets, not invented device observations. Direct-control initial color still comes from device reads.

Catalog version 2 retains the existing storage key and accepts version 1 definitions without lighting fields. Saving/editing never executes commands. Existing stable node/endpoint identity, partial results, explicit retry and stop semantics remain.

The executor validates capabilities before any write. It applies OnOff, optional level and optional color, then reads back every requested attribute. Exact levels and bounded HS/XY comparisons determine confirmation. Color clipping or missing readback is not reported as success. One 28-second deadline bounds the entire action; after timeout or target removal no later command is sent. The outer runner retains its 32-second bound. Already-sent native requests cannot be recalled.
