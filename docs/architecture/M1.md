# M1 — First Light

**Status: Conditional software acceptance; M2 development unblocked, hardware acceptance pending**

## Goal

Prove the first real Manisa Matter device path on physical hardware and turn that proof into a product-owned mobile control path.

## Hardware validation result

A real Matter-over-Wi-Fi touch switch was successfully commissioned from Android and its Matter endpoint was successfully controlled using the Manisa Direct Matter validation APK built from the pinned ConnectedHomeIP controller stack.

This proves the critical M1 protocol path:

```text
Android phone
    ↓ BLE commissioning
Matter touch switch
    ↓ Wi-Fi provisioning
Matter over Wi-Fi
    ↓ secure operational session
Android controller
    ↓
On/Off endpoint command
    ↓
physical switch output
```

The same device had previously been usable with the NXP Matter test application, giving Manisa a known-good reference controller when diagnosing commissioning or interaction regressions.

## Mobile integration boundary

Flutter must not depend on CHIPTool screens or raw ConnectedHomeIP APIs. The app talks to a small Manisa-owned controller contract:

```text
Flutter UI
    ↓
DirectMatterController
    ↓ platform channel
Android Manisa Matter bridge
    ↓
ConnectedHomeIP ChipDeviceController
    ↓
Matter-over-Wi-Fi device
```

Initial product-facing operations are:

- commission Matter-over-Wi-Fi from a setup payload
- discover OnOff-capable endpoints
- read OnOff state
- subscribe to OnOff state changes
- send On / Off / Toggle
- remove a commissioned device

Raw cluster IDs, TLV encoding, fabric internals, operational credentials, and connected-device pointers remain inside the native adapter.

## Hardware acceptance gate (non-blocking for M2 development)

By explicit user decision, M2 development proceeds while hardware checks remain pending. Final hardware acceptance still depends on reproducible evidence for the remaining hardware scenarios in `docs/testing/M1-test-register.md`:

- Wi-Fi recovery, device power-cycle recovery, Force-stop and phone restart
- physical-touch state propagation and every endpoint-to-relay mapping
- local operation without internet and offline removal behavior
- command, recovery and commissioning performance measurements

The versioned Test Bed Runner captures the evidence. CI validates its calculation and reporting logic but cannot mark physical tests as passed.

## Original first UI slice

Build the Android native bridge and wire it into the branded Flutter app. The first UI target is deliberately small:

```text
+ Add Device
    ↓
Scan Matter QR
    ↓
Choose Wi-Fi
    ↓
Adding device…
    ↓
Touch Switch
  [ Gang 1 ] [ Gang 2 ] [ Gang 3 ]
```

Endpoint count and state must come from the commissioned device, not from a user-selected `switch_1gang/2gang/3gang` assumption.
