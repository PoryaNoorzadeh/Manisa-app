# M0 — Foundation

**Status: Completed**

## Goal

Establish a production-shaped but minimal local-first foundation that can evolve into the Manisa Hub software stack while keeping Manisa ownership of the product API, data model, device identity, and capability model.

## Completed deliverables

- Go 1.27 modular-monolith service
- Versioned `/api/v1` boundary
- Liveness and readiness endpoints
- SQLite with WAL and foreign keys
- Home / Room / Device persistence and APIs
- Stable Manisa device identities independent of Matter Node IDs
- Container image and local Compose environment
- Open Home Foundation Matter Server integration behind a Manisa-owned controller boundary
- Matter commissioning and command execution
- Canonical capability descriptors and device-state normalization
- Matter event listener with reconnect behavior
- Realtime `device.state_changed` WebSocket events
- Local mDNS Hub advertisement and Flutter discovery boundary
- Local Hub pairing and Bearer-token authentication
- Flutter application foundation with Home/Room/Device loading, state, realtime updates, QR onboarding, and basic controls
- Direct Matter Android hardware-validation build for Matter-over-Wi-Fi testing without a Hub
- CI for Go formatting, vet, race tests, build, Flutter format/analyze/test, Flutter APK build, and Direct Matter APK build
- Architecture Decision Records for the foundational platform boundaries
- Updated project README and milestone documentation

## M0 acceptance

M0 is considered complete because the repository now has the core application boundaries, persistence, local API, Matter adapter boundary, realtime state path, mobile foundation, security bootstrap, deployment skeleton, and CI needed to move into hardware-first product validation without redesigning the platform foundation.

M0 does **not** imply production readiness. Production hardening, release signing, OTA/recovery, certification, fleet management, final cloud architecture, and final commercial security review remain later milestones.

## Next milestone — M1 First Light

M1 proves the end-to-end device path on real hardware:

```text
Android phone
    ↓
Scan Matter QR / setup code
    ↓
BLE commissioning
    ↓
Provision Matter-over-Wi-Fi device
    ↓
Discover actual endpoints
    ↓
Send per-endpoint On/Off commands
    ↓
Validate physical relay/touch-state behavior
```

The immediate M1 target is the prepared Matter-over-Wi-Fi touch switch. The Direct Matter Android controller is the fastest validation path. Once hardware behavior is proven, the native Matter-controller capability will be integrated into the branded Manisa mobile application for direct phone-to-device operation where that product mode is desired.
