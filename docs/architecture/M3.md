# M3 — Capability-based device experience

## M3.1 candidate: 0.11.0+15

OnOff remains the control capability. A separate, optional read of Descriptor
cluster 0x001D / DeviceTypeList attribute 0 discovers the product types reported
by each endpoint. Plug-in units 0x010A and 0x010B get Persian socket labels.
Other OnOff endpoints use a truthful single/multiple-output presentation. Endpoint
count is not evidence of the number of physical switch gangs. No dimming or
metering is claimed for a socket merely because its device type supports it.

The optional reader interface leaves existing controller mocks compatible. Type
metadata is cached alongside names, keyed by endpoint, with a missing-map default
for old installations. Discovery runs after state restoration, has a timeout,
and failures retain the existing controls and cached metadata. Commissioning,
fabric removal and OnOff command targets are unchanged.

Source contract checked against connectedhomeip v1.5.1.0:

- `src/controller/java/generated/java/matter/controller/cluster/clusters/DescriptorCluster.kt`
- `src/controller/java/generated/java/matter/controller/cluster/structs/DescriptorClusterDeviceTypeStruct.kt`
- `src/app/zap-templates/zcl/data-model/chip/matter-devices.xml`

## Acceptance and limits

Automated tests cover channel decoding, malformed/native error responses, JSON
round trips, legacy migration, endpoint identity, Persian labels, optional read
failure and slow/disposed UI behavior. Execution evidence is recorded separately
in the canonical register, not assumed from test creation.

Native Android compilation checks SDK compatibility. Fake controllers do not
prove native TLV decoding, BLE/network behavior, or a physical relay transition.
Real socket, mixed-output device, large text layout and hardware regression
remain manual acceptance items. Preserve the previous build as a rollback option;
this candidate is not a public-production readiness claim.

## M3.2 candidate: 0.12.0+16

LevelControl support is discovered by reading cluster 0x0008, CurrentLevel
attribute 0, across endpoints. The dimmer is shown only for endpoints that return
that attribute. A nullable CurrentLevel is presented as unknown and cannot send a
guessed slider value. Valid Matter levels 1..254 are converted to a Persian 1..100
percent presentation with tested boundary rounding.

The slider updates locally while the user drags but emits one MoveToLevelWithOnOff
command (0x04) only when the gesture ends. The native bridge bounds the raw level,
targets the exact endpoint, sends options mask/override zero, and the Flutter layer
re-reads CurrentLevel before accepting the new displayed value. A level-command
failure leaves the last confirmed value visible and does not mark unrelated
devices unavailable.

Capability endpoint identity is cached with the device using a backward-compatible
empty default. Current level itself is live state and is not persisted as truth.
Realtime changes made from the physical dimmer are not claimed by this step; they
remain a hardware acceptance item and will require a LevelControl subscription.

## M3.2.1 candidate: 0.12.1+17

Confirmed LevelControl endpoints now receive a dedicated CurrentLevel subscription
on `com.manisa/matter/level_events`. Keeping this separate from OnOff events avoids
changing the established switch stream contract. Reports are accepted only for a
device still present in the UI and an endpoint already confirmed by capability
discovery. Nullable reports return the UI to an explicit unknown level.

After MoveToLevelWithOnOff succeeds, the app reads both CurrentLevel and OnOff
before committing the displayed result. This covers the command's power-state
side effect. A failed confirmation keeps the previous confirmed display and shows
a Persian recovery message. Tests cover live level reports, OnOff readback, exact
endpoint targeting and a late report after widget disposal. Native compilation is
the gate for the additional EventChannel and subscription callback.

## M3.3 candidate: 0.13.0+18

Electrical readings are discovered from the attributes actually returned by
Electrical Power Measurement cluster 0x0090 and Electrical Energy Measurement
cluster 0x0091. The initial read-only surface supports ActivePower (attribute 8),
Voltage (4), ActiveCurrent (5) and CumulativeEnergyImported (1). A socket or
product label alone never enables this surface.

Native values retain the Matter units: milliwatts, millivolts, milliamps and
milliwatt-hours. Flutter converts them to watts, volts, amps and kilowatt-hours
without losing a real zero. Supported-null is displayed as not received, while
an absent attribute stays hidden. Digits and decimal separators are Persian;
QR, SSID and credentials remain untouched.

Only capability metadata is persisted. Measurements are live observations and
are read again at startup, foreground refresh and user refresh. If an optional
measurement read fails, the previous observation stays visible with a stale
indicator and OnOff/LevelControl remain usable. Software tests cover units,
zero/null/unsupported distinctions, persistence migration, widget rendering and
read failure. Native compilation validates the v1.5.1.0 TLV calls; accuracy and
live report timing still require physical metering hardware.
